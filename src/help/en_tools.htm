Tool calling

Tool calling means the cloud service may ask this program to do something on your computer, the program does it, and the result is sent back so the service can summarise it in plain language. You see every step in the conversation pane.

Available tools

ToolWhat it doesConfirmation
get_system_infoOS, CPU, memory, disks, screen, code pageNo
list_dirList files and subfolders of a folderNo
read_fileRead a text file (decoded as GBK/ANSI)No
write_fileWrite text to a file (GBK, overwrites)Yes
run_commandRun a command through cmd.exe /c and capture outputYes
open_pathOpen a file, folder or URL with the default programYes
set_clipboardPut text on the clipboardNo

The confirmation box

Writing files, running commands and opening things always asks first:

The assistant wants to perform this operation. Allow it? Run in the command prompt: cmd.exe /c dir D:\work (If unsure, choose No.)

Answering No tells the assistant the request was refused; it will not retry and instead explain and ask what to do differently. The box is never auto-approved.

Please be careful: do not click Yes out of habit. A prompt can be crafted so that the service emits del /s /q or format. If you do not recognise the command, say No.

Turning it off

Clear Allow the assistant to use local tools at the bottom of the main window and it will only give written advice.

How many tool calls per question

Each turn may run at most 8 tool calls; after that the program stops and asks you to split the task.

Encoding

Internally the program uses the system code page (936, GBK, on Simplified Chinese Windows) while the network API uses UTF-8; conversion is automatic. Files that are themselves UTF-8 will look garbled, because programs of this era assume GBK.
